Editor Visual Syntax ​

This page documents the editor-only visualization layer used by the playground.

It does not change omniui source syntax. It only changes how the editor helps you scan and understand the same text.

What The Editor Emphasizes ​

The editor visually separates:

  • layout directives such as ~ Stack
  • component targets such as (Button.primary)
  • component tokens such as .primary, .ghost, .sm
  • bindings such as @email
  • markdown node types such as headings, paragraphs, lists, quotes, code blocks, and dividers
  • checkbox and radio shortcuts

Markdown Badges ​

The editor adds subtle badges to common Markdown node types:

  • H1, H2, H3 for headings
  • P for plain paragraph lines
  • LIST for list-style nodes
  • PROP for component multiline prop lines (- key, - key=value)
  • ❝ for blockquotes
  • </> Code for fenced code blocks
  • — Divider for Markdown ---

These are visual aids only. The underlying text remains unchanged.

Shortcut Visualization ​

Markdown shortcuts are shown with more semantic affordances in the editor:

OmniUI
Codeomniui
[ ] Label
[x] Label
( ) Label
(o) Label

The editor renders them with control-like markers and a semantic suffix chip:

  • [ ] → ☐ Label + Checkbox
  • [x] → ☑ Label + Checkbox.checked
  • ( ) → ○ Label + Radio
  • (o) → ● Label + Radio.selected

This is still only a visualization layer. The original source string is preserved.

Component Chips ​

Component refs are rendered as:

  • a rounded component chip
  • token chips for each component token
  • an accent chip for bindings

Example:

OmniUI
Codeomniui
[Search UX/UI systems](Input.search.fill@email)

appears in the editor as a more scannable sequence of chips for Input, search, fill, and @email.

For component lines using:

OmniUI
Codeomniui
[Label](Avatar.initials.md)

the editor applies a specific rule:

  • a component-kind badge (for example AVATAR, INPUT, TEXT, NAVITEM) appears at the left of the line
  • the target inside () is rendered as highlighted text (colored name/tokens) instead of heavy chips
  • this keeps [] and () visually distinct while preserving source readability

Current Scope ​

The current playground editor visual layer covers:

  • layout directives
  • component refs and tokens
  • markdown headings
  • paragraphs
  • blockquotes
  • fenced code blocks
  • Markdown dividers
  • checkbox shortcuts
  • radio shortcuts
  • generic list items
  • component multiline prop rows

This does not add new parser syntax. It is an editor affordance built on top of the same omniui source.

Virtual Templates Mode ​

The preview toolbar includes Pattern Mode for repeated layout editing.

When enabled, the editor infers repeated sibling structures (virtual templates), highlights representative instances, dims unrelated UI, and opens a floating template editor popover near the selected template so layout patches can be applied to all matching items at once.

See: /language/virtual-templates
