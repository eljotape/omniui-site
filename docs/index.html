OmniUI ​

OUI is a minimal UI layout language designed to describe user interfaces using a simple, readable tree structure.

Instead of writing verbose UI code, OUI lets you define layouts, components, and structure using a small set of primitives.

OUI documents are:

  • easy to read
  • easy to edit
  • easy to share
  • easy to analyze
  • LLM-friendly

Why OUI ​

Modern UI code mixes:

  • layout
  • styling
  • logic
  • behavior
  • framework conventions

This makes it difficult to understand the structural intent of an interface.

OUI focuses on structure first.

A OUI document describes:

  • layout hierarchy
  • component composition
  • spatial relationships
  • UI intent

without requiring a framework or runtime.

LLM-friendly by design ​

OUI was designed to be easy for language models to read, generate, and transform.

Unlike HTML or JSX, OUI uses:

  • consistent tree structures
  • minimal syntax
  • predictable layout primitives
  • low nesting complexity

Example:

OmniUI
Codeomniui
~ Ui
  ~ Stack gap=lg

    ~ Form showLabels

      [Email address*](Input.email.fill)
        - placeholder="name@example.com"

      [Password*](Input.password.fill)

      [Sign in](Button.primary)

Even without rendering, the structure of the interface is immediately clear.

This makes OUI particularly effective for:

  • AI-generated UI samples
  • automated layout transformations
  • UI refactoring tools
  • design system documentation
  • intelligent editors

Read the full deep dive: LLM-Friendly Design.

Why OUI works well with AI ​

OUI reduces ambiguity.

Compared to typical UI code:

HTML / JSX:

html
<div class="flex flex-col gap-4">
  <label>Email</label>
  <input type="email" placeholder="name@example.com"/>
</div>

OUI:

OmniUI
Codeomniui
[Email](Input.email.fill)
  - placeholder="name@example.com"

The intent of the UI element is explicit.

This allows language models to:

  • infer patterns
  • transform layouts
  • generate samples
  • identify repeated structures

with much higher reliability.

See also: LLM-Friendly Design.

Designed for structured UI editing ​

Because OUI describes UI structure explicitly, it enables tooling such as:

  • visual layout editors
  • pattern detection
  • virtual templates
  • automated UI refactoring
  • documentation generation

The same document can be used for:

  • documentation
  • editing
  • preview
  • analysis

Key ideas ​

Layout is explicit ​

OUI uses a small number of layout primitives:

OmniUI
Codeomniui
Ui
Stack
Grid
Spacer
Divider

These primitives describe how elements are arranged, not how they look.

Components are declarative ​

UI elements are expressed directly in the tree.

Example:

OmniUI
Codeomniui
[Email address*](Input.email.fill)
  - placeholder="name@example.com"

Structure is readable ​

OUI documents are designed to be readable almost like outlines.

  ~ Stack gap=lg

What OUI is for ​

OUI is designed for:

  • UI documentation
  • layout exploration
  • design system examples
  • component samples
  • structured UI editing
  • AI-assisted UI generation
  • automated UI transformations

What makes OUI different ​

OUI emphasizes:

  • structural clarity
  • minimal primitives
  • explicit layout
  • readable documents
  • AI-friendly syntax

This makes OUI particularly useful for:

  • design systems
  • documentation sites
  • UI libraries
  • intelligent UI tooling
