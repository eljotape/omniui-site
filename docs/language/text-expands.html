Text Expands ​

This page documents the inline text transformations that happen at render time.

Text expands are not a separate AST node. They are render-time behaviors applied to labels and text-like content.

What is covered ​

  • inline emoji-to-icon conversion
  • inline emoji-to-badge conversion
  • label wrapping defaults
  • explicit wrap / nowrap
  • leading icon extraction

Inline Emoji Icons ​

Supported inline emojis can render as SVG icons instead of literal text.

Examples:

OmniUI
Codeomniui
[[search](Icon) Search](Input.search.fill)
[⭐ Starred](NavItem.md)
[[chart-up](Icon) [save](Icon) [thumb-up](Icon) [thumb-down](Icon)](Text.lg)

Notes:

  • the supported icon catalog is documented in /language/icons
  • these emojis go through the semantic icon mapping pipeline
  • they can appear as a leading icon or inline inside tokenized labels
  • when rendered as icons, they inherit the text size of the line they belong to
  • they are vertically centered against that text line instead of using a separate control icon size

Inline Emoji Badges ​

Some enclosed alphanumeric emojis are treated as inline badges instead of icons.

Supported today:

  • 🅰️, 🅱️, 🆎, 🆑, 🅾️
  • 0️⃣ to 9️⃣
  • enclosed 10 badge token

Examples:

OmniUI
Codeomniui
[Plan 🅰️](Text.md)
[Steps 1️⃣ 2️⃣ 3️⃣](Text.sm)
[Release [10](Badge)](Button.secondary.md)

Behavior:

  • they do not use the icon catalog
  • they render as small badge chips
  • the visible badge content is the alphanumeric payload, for example:
    • 🅰️ -> A
    • 🆎 -> AB
    • enclosed 10 token -> 10

Leading Icon Extraction ​

When a supported inline icon emoji appears at the start of a label, many components treat it as the leading icon for the component.

Examples:

OmniUI
Codeomniui
[[search](Icon) Search mail](Input.search.fill)
[✉️ Gmail](NavItem.active)
[➕ Create](Button.primary.md)

This is different from inline badges:

  • a supported icon emoji at the start can become the component leading icon
  • a badge emoji at the start stays part of the label flow and renders as a badge, not as a leading icon

Wrap and NoWrap ​

Text expansion also includes line-breaking behavior.

Current defaults:

  • Text wraps by default
  • Button, NavItem, Input, ProgressBar, Select, Slider, SpinButton, and Menu stay single-line by default

Explicit tokens:

  • wrap
  • nowrap

Examples:

OmniUI
Codeomniui
[This paragraph wraps by default in narrow space.](Text.sm)
[Single line metric](Text.sm.nowrap)
[Long action label that may need two lines.](Button.secondary.sm.wrap)

Plain Text Fallback ​

If inline content does not match a supported icon emoji, badge emoji, or component pattern, it remains plain text.

That means:

  • unsupported emojis stay literal
  • normal words stay literal
  • text expansion is additive, not destructive

Scope ​

These behaviors are currently exercised in:

  • Text
  • Button
  • NavItem
  • Input
  • ProgressBar
  • Select
  • Slider
  • SpinButton
  • Menu

Some expansions are component-specific:

  • leading icon extraction is mainly used by control-like components
  • wrapping defaults depend on the component family

Reference ​

  • icon catalog: /language/icons
  • explicit icon component: /language/icon
  • text behavior: /language/text
  • renderer defaults: /language/rendering-rules
