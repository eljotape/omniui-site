Skeleton Token ​

Overview ​

  • skeleton is a rendering token, not a standalone component.
  • Apply it to a component or container when the interface should render loading placeholders instead of real content.

Use Cases ​

  • Use skeleton while cards, lists, forms, feeds, or profile blocks are loading.
  • Use it to preserve layout stability before real content becomes available.

Component Mapping ​

  • Text becomes one or more bars
  • Avatar becomes a circle
  • markdown image placeholders and Image.skeleton become rectangles
  • Button becomes a rounded placeholder
  • Card.skeleton becomes a card-like placeholder structure
  • other supported components fall back to shape-equivalent placeholders

Propagation ​

  • If a container is declared with skeleton, the renderer propagates skeleton mode to its renderable children.
  • This applies to structures such as Stack skeleton and Grid skeleton.
  • Container-level skeleton does not add a background fill on its own.
  • Background fill appears only when the container already has an explicit surface mapping (for example surface=muted or surface=raised).
  • No child override is documented yet.

Current Notes ​

  • The old Skeleton.* component form is no longer the documented strategy.
  • The preferred pattern is to add skeleton to the real component or to the containing layout.
